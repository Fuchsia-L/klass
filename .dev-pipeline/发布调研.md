# klass 发布调研

> 调研时间：2026-03-17

## 方案对比

### 方案 A：Google Play Store

**费用：** 一次性 $25（约 ¥180）

**流程：**
1. 注册 Google Play Developer 账号（需 Google 账号 + 信用卡/借记卡支付 $25）
2. 新个人开发者账号政策（2024.12 更新）：
   - 上架前必须进行**封闭测试**
   - 至少 **12 名测试人员**持续参与 **14 天**
   - 满足后才能发布正式版
3. 用 Expo EAS 构建 + 提交：
   - `eas build --platform android` 生成 .aab（App Bundle）
   - `eas submit --platform android` 提交到 Play Console
   - 需要创建 Google Service Account + 下载 JSON key
4. 商店信息：截图、描述、隐私政策页面、内容分级问卷

**优点：** 全球分发、EAS 一键构建提交
**缺点：** 封闭测试要凑 12 人等 14 天、需要翻墙注册和管理

---

### 方案 B：国内安卓应用商店（华为/小米/OPPO/vivo/应用宝 等）

**费用：** 免费注册（大部分平台）

**流程：**
1. 注册各平台开发者账号（需实名认证，身份证）
2. **⚠️ 核心门槛：APP 备案**
   - 2023.9 起国内要求所有 APP 必须在工信部完成备案
   - 个人开发者可以备案，但需要提供域名（已备案的域名）
   - 部分商店要求**计算机软件著作权（软著）**——办理周期 1-3 个月
3. 部分平台要求企业认证（华为应用市场需要营业执照）
4. 上传 APK、截图、描述、隐私政策
5. 各平台单独审核，规则不统一

**优点：** 免费、覆盖国内用户
**缺点：** 备案麻烦、可能要软著、华为需企业资质、每个商店单独提交

---

### 方案 C：GitHub Releases + 直接分发 APK

**费用：** 免费

**流程：**
1. 生成签名 APK（正式 keystore，不用 debug）
2. 上传到 GitHub Releases
3. 用户直接下载安装（需开启"允许未知来源"）

**优点：** 零成本、立刻可用、无审核
**缺点：** 没有自动更新、用户需手动安装、触达范围小

---

### 方案 D：F-Droid / IzzyOnDroid

**费用：** 免费

**流程：** 开源项目可提交到 F-Droid，自动构建分发

**优点：** 开源社区友好、自动更新
**缺点：** 用户群小、审核周期长

---

## 推荐路线

### 短期（现在就能做）
→ **方案 C：GitHub Releases**
- 生成正式签名 APK，挂到 GitHub
- 成本为零，今天就能做
- 先让身边的人用上

### 中期（1-2 周准备）
→ **方案 A：Google Play**
- 注册开发者账号
- 找 12 个人参加封闭测试（同学、ACM 群友、训练营的人）
- 14 天后发布正式版
- 这个过程本身也是推广

### 长期（如果想做大）
→ 国内应用商店，但门槛高，建议等有一定用户基础再考虑

---

## 发布前需要做的

不管走哪条路，都需要：

1. **正式签名** — 生成 release keystore（替换 debug keystore），妥善保管
2. **版本号管理** — app.json 里的 version + android.versionCode
3. **隐私政策** — 即使 GitHub 分发也建议写一份（简单的 markdown 就行）
4. **应用图标 + 截图** — Play Store 需要至少 2 张截图 + 512x512 图标 + 1024x500 feature graphic
5. **UI 美化** — 现在是功能态，发布前至少过一轮视觉（和 Gemini 讨论）
